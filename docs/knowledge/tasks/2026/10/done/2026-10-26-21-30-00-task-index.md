# Task index: what has been asked, by meaning

- Status: Done
- Last Reviewed: 2026-10-26
- Source Of Truth: src/task-index.js, test/unit/task-index.test.js, AGENTS.md (Protocol surface)

## Goal

Keep every task with a vector of what it computes, so the questions asked of the server can be
searched by meaning and clustered into themes over a period (optionally narrowed to a phrase).

## Decisions

- A record of the questions, never a way to the data: answers carry no task id, context id or table
  (the user ruled out reusing another task's results — they may not fit and only cause trouble). The
  method is shown: a found task's input without what names stored work (`howOf`).
- On prod the memory search already runs on OpenAI (`memory_semantic: true`), so the index uses the same
  embedder there.
- No new field on the tools (the user declined a `question` field): the text is built from the
  context's name and description and the meaningful strings of the input.
- Vectors: the memory embedder (MEMORY_EMBEDDINGS, OpenAI) at 256 dimensions; without it a local
  TF-IDF vector over the tasks of the window, so it works on every deployment.
- Exposed as a semantic_index view (`{ tasks: { search } | { themes: true, about?, clusters? } }`), not
  a new tool.
- Tasks started before the index are backfilled from the job registry when the view is first read.

## Verification

`node --test test/unit/task-index.test.js` (in-memory and SQLite stores, a stand-in embedder, the
engine's task start), plus the unit suite.
