# Tests and evals remove the temporary directories they make

## Status

done

## Last Reviewed

2026-10-14

## Last Used

2026-10-14

## Context

The unit and integration tests made temporary directories with `mkdtempSync(join(tmpdir(), '<prefix>-'))`
and never removed them. Two weeks of runs in one environment left about 110,000 of them in /tmp
(~26 GB) and filled the disk. A baseline run of the original unit suite here left 374 new entries.

## Objective

A full run (`npm run lint:names`, `npm test`, `npm run test:integration`, `npm run eval:check`, on
`DBT_ENV=dbt-v2`) leaves no new entry in `os.tmpdir()`, and still passes.

## Expected Result

Every temporary directory under test/ and evals/ is made by one helper and removed when its run
ends; what holds files in it is closed first; the tests keep asserting on data.

## Scope

- test/ (unit, integration, shared helpers), evals/harness.mjs, the reproduction script in
  docs/memory-and-filter-guard-example.md.

## Out Of Scope

- src/: it removes its own temporary directories (src/dbt/v1.js `dbt-target-`, `mfq-`); reported, not changed.

## Investigation

- node:test (Node 22) runs `after` hooks FIFO; a module-level `after()` called inside a `before()`
  hook attaches to that hook and runs when it ends — a helper registering its cleanup that way
  would remove the workspace a `before()` sets up before the first test.
- `ValueIndex` and `JobManager` close only a store they opened themselves: `engine.valueIndex.close()`
  leaves the engine's store open; `engine.close()` releases it.
- No `sz-` prefix exists in the repository or its history: those came from ad-hoc scripts.
- What the server's own tools leave in the temp dir in normal operation (reported, src/ unchanged):
  * dbt-duckdb (dbt 1.x: the python stage, retentioneering) writes each Python model to a
    `NamedTemporaryFile`, imports it and unlinks the `.py` only — its bytecode stays as
    `/tmp/__pycache__/tmpXXXXXXXX.cpython-313.pyc`, one per model run (57 files, 2.4 MB per full run);
  * MetricFlow's `mf` (dbt_metricflow/cli/main.py, `UpdateChecker`) keeps one fixed-name
    `update_checker_cache.pkl` there; it does not grow.
- Pre-existing failure, not this task's: condition-grammar.test.js "a text column … compared with a
  boolean" passes `op: 'ne'`, which the condition grammar (`OPS`: `neq`) refuses — same on 6c9fb33.

## Decision

`tempDir(prefix)` removes its directories on the process's `exit`: after every hook of the file
(the ones that close stores, stop the warehouse) and once no child process is left. `removeTempDir`
removes one sooner (an eval case, the warehouse's `stop()`).

## Steps

1. `test/helpers/temp-dir.js`; every call site routed through it.
2. Close the file-backed stores tests left open.
3. Guard: `test/unit/temp-dir.test.js`; the rule in AGENTS.md (Testing).
4. Full run on dbt-v2 with /tmp listed before and after each step.

## Verification

Full run on `DBT_ENV=dbt-v2`, the entries of `os.tmpdir()` listed before and after each step:

| step | result | entries |
|---|---|---|
| start | | 26 |
| `npm run lint:names` | pass | 26 |
| `npm test` | 597 / 597 | 26 |
| `npm run test:integration` | 497 / 498 — the pre-existing condition-grammar failure | 28 |
| `npm run eval:check` | all 14 cases hold | 28 |

The two new entries are the tools' own (`__pycache__`, `update_checker_cache.pkl`, above); no
directory a test or an eval made is left. The original unit suite alone left 374.

## Solution

One helper, `tempDir(prefix)`, removing on exit; every call site routed through it; the stores that
were left open closed in the tests; a guard test and the AGENTS.md rule so the pattern does not return.

## Result

Done. Left as reported: the two tool artifacts (src/ unchanged — e.g. `PYTHONDONTWRITEBYTECODE=1` in
the environment src/dbt/process.js gives dbt should stop the `.pyc` files — not tried) and the condition-grammar
test's `op: 'ne'`.
