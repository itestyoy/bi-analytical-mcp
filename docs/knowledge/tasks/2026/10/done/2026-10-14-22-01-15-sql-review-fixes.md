# Fixes of a review of the schema-to-SQL path

## Status
done

## Last Reviewed
2026-10-14

## Context
A code review of the tool schemas and their transformation into SQL (src/schema*, src/pipeline/*,
src/conditions.js, src/dialects/*) found 15 problems: two security ones (a string literal quoted the
DuckDB way on BigQuery; a raw expression could end the statement), silent wrong rows on DuckDB (a
compute over an existing column name), BigQuery-only failures (time functions and the validity window
on DATE, a boolean constant against text, typed payload keys read as text) and rows that differed
between the warehouses (concat with NULL, array length of a missing array, elapsed_days, a stored
array_contains, unpivot's value type, a partition bound from an offset timestamp, a second text-to-
number writer).

## Decisions
- A string literal is the dialect's: DuckDB doubles the quote; BigQuery writes GoogleSQL escapes. The
  shared export writes `CHR(n) || …` for a quote, backslash or control character, which both read
  alike; a NUL is refused.
- A raw is ONE expression: `;`, a comment opener/closer or unbalanced parentheses outside quoted text
  are refused.
- A missing array has length 0 on both warehouses; concat is missing when any part is; elapsed_days
  floors on both; secondsBetween is exact to the microsecond on both.
- `fromText` also reads a flag (`'true'` / `'false'`, any case, the same whitespace trimmed on both)
  and a moment (GoogleSQL's canonical form; DuckDB refuses what BigQuery would).
- A time constant with an offset is written as its UTC instant (to the microsecond) and bounds the
  partition by its UTC day; an offset spelling BigQuery does not read is refused.
- Every boolean a compute stage or a semantic dimension stores is never NULL.
- A compute / unnest naming an existing column is refused; unpivot's value column has the folded
  columns' one type (numbers folded through FLOAT64, moments through TIMESTAMP on BigQuery; other
  mixes refused).
- A TIME-of-day column is tracked as `time_of_day` (only `hour` is a date part of it); it is no longer
  a MetricFlow time dimension.
- The moment helpers moved to a leaf module, src/moment.js (an import cycle otherwise).

## Verification
DuckDB: data tests in test/integration/sql-review-{a,b,c,d}.test.js, refusals in
test/unit/sql-review-{a,b,c,d}.test.js; the full set on dbt-v2 (see the commit). BigQuery: NOT run —
no access was granted for this work; its SQL was reviewed against the GoogleSQL documentation only.

## Left open
- castExpr(x, 'string') writes floats, decimals and timestamps differently on the two warehouses.
- BigQuery's jsonExtract gives NULL for a payload key holding an object, DuckDB its JSON text (no
  catalog declares such a key today).
- BigQuery's unnest `|> DROP <name>_e` is not checked against an existing column of that name.
- BigQuery recentSince / sinceTimestampMs on a DATE time axis; LIKE reads a backslash differently.
