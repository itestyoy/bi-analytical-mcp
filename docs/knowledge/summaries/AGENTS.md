# Summaries

Quick orientation only.

- Treat summaries as hints, not truth.
- Update them when conclusions change.
- Prefer one summary per repo or domain.
- Reuse existing summaries when possible.
- Keep them short and linked to the current source of truth.
- Create summary notes as `docs/knowledge/summaries/YYYY-MM-DD-HH-MM-SS-short-title.md`.
